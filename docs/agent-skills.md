# 项目 Agent skills 使用与维护

## 目录职责

| 位置 | 用途 |
|---|---|
| `.agents/skills/<skill-name>/SKILL.md` | 项目内可发现、按任务触发的 Agent 开发指导；复杂或条件性流程放在同目录 `references/` |
| `docs/skills/manifest.yaml` 与其条目 | Study Plan 领域设计契约和按需加载知识的唯一索引 |

Agent skill 用来指导模型完成工作；`docs/skills/` 用来提供领域知识。两者可以互相链接，但不能互相替代。Skill 文本不会参与权限判定，也不会授予任何运行时能力。

## `study-plan-fast-development` 做什么

[`study-plan-fast-development`](../.agents/skills/study-plan-fast-development/SKILL.md) 将附件中的快速交付规范转成项目可复用的开发流程：

- 按任务规模明确目标、必要的不变量、验收条件和成比例的验证；局部小改动只需简短说明。
- 以最小主流程切片交付，避免无关重构和提前优化。
- 用 P0/P1/P2/P3 区分必须解决的问题与可以记录的问题。
- 对失败建立根因假设、限制盲目修补，并将非阻塞问题记入技术债。
- 根据任务读取 RAG、Memory、Token、延迟和并发专项评测方法。
- 提醒为后续调优保留脱敏、可测量的观测数据。

它不改变项目的授权、安全边界、用户指令或业务运行行为。

## 适用场景

当任务涉及 Study Plan 项目中的功能开发、缺陷修复、相关测试/回归选择、跨模块集成，或基于数据的 RAG、Memory、Token、延迟及并发评估时使用。

纯概念问答、与本项目无关的仓库、只需查阅外部技术文档的任务不需要加载它，除非用户明确要求。遇到数据安全、权限或不可恢复的数据风险时，风险优先级高于常规调试预算和交付速度。

## 使用方法

项目 Agent skills 通过名称和描述参与任务匹配；Codex 判断任务命中范围时会加载相应技能。需要明确指定时，可在请求中写：

```text
请使用 $study-plan-fast-development 完成这个功能。先列出 Goal、Invariants、Scope、Out of Scope、Acceptance 和 Validation，再实施。
```

按当前任务读取所需内容：

- 日常功能或缺陷处理：先读 [技能入口](../.agents/skills/study-plan-fast-development/SKILL.md)。
- 测试失败、调试预算或复现问题：再读[问题分级与调试流程](../.agents/skills/study-plan-fast-development/references/triage-and-debug.md)。
- RAG、Memory、Token、延迟或并发评估：再读[评测与优化流程](../.agents/skills/study-plan-fast-development/references/optimization.md)。

简单的局部代码改动只需说明目标和验证；多层或重要边界改动再补充不变量、范围、契约和验收条件。完成标准要能对应到用户验收条件和实际验证证据。

## 使用规范

- 按实际任务范围加载技能；用户的明确要求和更高优先级的安全约束始终优先。
- 先保护数据、权限和核心用户流程，再处理普通优化。P0/P1 不得因预算耗尽而直接延期。
- P2/P3 可以延期，但要记录复现条件、影响和后续验证方法；不能把“之后再看”当作已解决。
- 开发中验证受影响的单元、契约与集成路径；功能完成时覆盖当前模块和相邻关键回归。跨模块改动要覆盖涉及的模块与边界，但不因“跨模块”三个字自动跑全量。
- 全量测试由用户要求、具体任务计划、里程碑或发布门禁、或无法用定向验证圈定的实际风险触发；先说明触发依据，通常在最终检查点跑一次。CI 的 PR 全量门禁照常执行；若同一提交已在 CI 通过，且没有明确的本地执行要求或未解决风险，避免重复本地全量运行。
- 日志保留脱敏指标和稳定标识，禁止记录生产环境敏感正文。
- 若技能建议与仓库现有约定冲突，先查明适用边界并更新技能，不能机械套用过时假设。

## 维护机制

项目维护者负责审核技能。至少每季度复审一次；项目里程碑或开发阶段变化时同步复审。若使用中连续出现同类误触发、错误延期、无效调试预算或不适用的验证建议，应立即针对证据修订，不等待周期复审。

复审时检查：

1. 描述中的触发场景是否仍然准确、足够具体。
2. P0/P1 边界是否覆盖当前数据、安全和主流程风险。
3. 调试预算是否减少盲目修改，同时没有阻止关键问题解决。
4. 测试、专项评测和技术债路径是否仍符合仓库现状。
5. 参考文档、示例命令和本地链接是否有效，内容是否与技能入口重复或矛盾。

更新流程：

1. 记录触发修订的具体任务、失误或项目阶段变化。
2. 只修改对应段落或参考文档；单个案例不能证明需要增加普遍规则。
3. 更新 `SKILL.md` 中的 `metadata.version` 和 `metadata.last_reviewed`。
4. 本地运行 `python tools/skills/check_agent_skills.py`，并人工走读局部修改、跨模块改动和明确要求全量门禁的场景。
5. 在变更评审中确认描述、使用指南和引用同步；CI 的 Agent skill 校验必须通过。

重命名或移除技能前，先查找 `$skill-name` 调用示例、文档链接和 Agent 工作流引用，并同步更新。不要删除仍被引用的技能或参考文档。

## 维护检查

```powershell
python tools/skills/check_agent_skills.py
```

该检查验证格式、命名和本地链接，不代表技能决策质量已被证明。触发条件和是否延期问题仍须通过实际开发案例定期复核。
