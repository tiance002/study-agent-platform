# 第七轮计划：普通用户学习工作台

## 目标

把现有 Cookie API 收进一个不依赖终端的 React 工作台。第一屏直接进入学习空间：
用户兑换邀请后可以创建项目、开启会话、提问、查看异步状态、读取经过校验的引用、
登记资料和保存计划。沿用关键词检索与现有 worker，不在本轮扩大检索算法范围。

## 设计方案

### 视觉语言

- 色彩：`#102A43` 深海蓝（结构与文字）、`#F5F7FA` 雾白（页面底）、`#FFFFFF` 纸白（工作区）、
  `#D64545` 朱砂红（错误/危险）、`#2F855A` 松绿（已完成/已验证）、`#D69E2E` 暖金（等待/提醒）。
- 字体：系统中文无衬线负责可读性；`ui-monospace` 仅用于引用坐标、运行 id 和状态码，避免把整页做成开发者控制台。
- 布局：左侧是项目导航，中央是当前学习流，右侧是可收起的证据/状态栏。桌面三列，移动端按“项目 → 主工作区 → 证据”顺序堆叠。
- 特色：把“学习证据”作为回答旁边的窄轨道，而不是装饰性卡片；每条引用直接带资料名、版本和原文范围。

### 结构草图

```text
┌──────────────┬──────────────────────────────┬──────────────┐
│ 项目          │ 会话 / 计划 / 资料            │ 证据与状态    │
│ 新建项目      │ 提问输入                      │ 来源          │
│ 项目列表      │ 消息时间线                    │ 引用坐标      │
│               │ 运行状态与回答                │ 摄取/预算状态  │
└──────────────┴──────────────────────────────┴──────────────┘
```

### 交互边界

- 浏览器只使用 HttpOnly Cookie，不在页面保存或发送 Bearer token。
- 所有写请求自动带 `Idempotency-Key`；服务端错误码原样映射为可行动的界面状态。
- 教学运行只轮询 durable status；刷新页面重新读取运行与消息，不重复创建请求。
- `succeeded` 只展示服务端已校验的引用；`reconciliation_required` 禁用重试按钮并明确需要处理。
- 加载、空数据、失败、窄屏、键盘焦点、`prefers-reduced-motion` 都是首版状态，而不是装饰补丁。

- [x] `frontend/index.html` 不再依赖终端签发 Bearer token。

- [x] 刷新页面后当前项目、会话、消息、计划和最后一次运行状态从 API 恢复；重复点击不会重复写入。
- [x] 桌面与 390px 移动视口无横向溢出，键盘焦点可见，核心按钮可通过 accessible name 定位。
