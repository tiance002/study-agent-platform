# ADR-014：子任务运行时（ChildRun）与 MCP 准入

- **状态：** 已接受
- **owner：** 待指派
- **决策日期：** 2026-09-18
- **到期复审：** 2027-03-01

## 背景

需要应对两类需求：一是长上下文任务应把中间工具调用留在子上下文、只把结果汇总回主对话；二是应尽量复用成熟 MCP server，避免重复自建连接层。

直接实现会撞上三条既有不变量：

- 不变量 #10：模型摘要不能自动去污点。**如果「汇总」是让子 agent 自然语言复述一遍，该复述即为新的 tainted 派生值**，同时引用溯源与 `display_policy` 判定一并失效。
- 不变量 #4：capability token 只减不增。子 agent 若被授予独立权限，等于新增一条扩权路径。
- 不变量 #7、#8：预算与未知状态不得失控。子 agent 若可递归 spawn，预算树与循环上限会被分裂绕过。

## 候选方案

| 方案 | 优势 | 劣势 |
|---|---|---|
| A. 不引入子 agent，全部在主对话完成 | 无新增抽象，谱系天然完整 | 长任务上下文爆炸，主对话被工具噪声占满 |
| B. 子 agent 可递归、可自持授权、散文摘要回传 | 灵活性最高 | 权限旁路、谱系断裂、预算分裂、审计缺口 |
| C. 深度上限 1 + 权限从父派生 + 结构化信封回传 | 省上下文且不破坏不变量 | 需要信封 schema 与校验实现 |

## 已选方案

**C。** 具体规则：

1. ChildRun 是 `WorkflowRun` 的下级执行单元，**不是新的授权主体**。
2. capability token 从父 run 派生，只减不增；默认只持 A0/A1；A2/A3 必须回主对话走确认流程。
3. 不可递归 spawn，**首版深度硬上限 1**；放宽需新 ADR。
4. 回传必须为结构化信封：`artifacts[]`（含 `content_hash`）、`claims[]`（含 `evidence_refs` 与 `kind: sourced|inference`）、`taint`、`status`、`issues[]`。`issues[].code` 使用 knowledge 域闭集 `EvidenceIssueCode`，并携带 claim/source 引用、可重试性与下一动作；自然语言只能是 `claims[].text`。
5. **上下文隔离 ≠ 证据隔离 ≠ 审计隔离 ≠ 预算隔离**：只隔离主对话上下文，其余三者旁路。
6. 不下放的场景：需多轮澄清、需实时确认的副作用、需连续上下文的教学对话、延迟敏感路径。预计任务本身消耗低于约 3k token 时不下放。

### MCP 准入（协议复用、边界自建）

接入前须全部满足：工具集合有限且有明确边界；每个工具可声明幂等或可查询对账；版本可固定且许可证已核验；无隐式出网或出网目标可白名单；响应大小可限制；维护状态与 owner 明确。

包装层要求：重命名为内部 `tool_id` 并收窄参数 schema；返回文本一律视为 tainted；**无幂等声明者最高只给 A1**；`tools/list` 描述不得作为策略输入或直接进入 system prompt；schema 按需加载。

不接受：远程代码执行类、无边界文件系统类、自动发布或支付类、无法固定版本类、需长期凭据且无法收窄 scope 类。

## 证据

- 不变量 #4、#7、#8、#10 的落点；`03` 号规格 §10、`05` 号规格 §4 与 §6。
- 上下文分类与压缩规则见 `02` 号规格 §2.1。

## 重新评估触发条件

- 出现单任务需超过 2 层分解且深度 1 无法表达的真实需求。
- 信封字段被证明不足以表达某类子任务结果（连续 3 次需要扩展字段）。
- 某 MCP server 通过准入后仍发生安全或可靠性事故。

## 回滚方案

停用 ChildRun：所有任务回到主对话执行，信封 schema 保留用于跨模块数据传递。MCP 部分可按 server 逐个停用，回退到自建工具适配器。回滚不影响 Policy Gateway、预算树与审计链路。
